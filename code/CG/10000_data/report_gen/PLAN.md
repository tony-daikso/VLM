# CG CT 報告草稿生成規劃

更新：2026-11-09
目標：讓 OWL 模型（Merlin 訓練、CG10k 推論）產生報告草稿，減少放射科醫師打字與重複描述的時間。

## 1. 現況

### 1.1 已有的資產

| 項目 | 位置 | 說明 |
|---|---|---|

| 14 類報告標籤 | `data/CT/CG/10000_data/disease14_qwen.csv` | Qwen 從報告抽出的 yes/no/not_mentioned 標籤 |
| OWL 推論結果 | `data/CT/CG/10000_data/owl_infer/best/probs_best_main.csv` | 6,970 例 C+ 主序列，14 類 logit（每類用 CG 最佳方法） |

### 1.2 報告分析（10,000 份）

- 全部是英文，平均約 180 字、16 句 findings。
- 結構：臨床資訊 → 掃描技術 → 比較前次 → Findings → IMP。IMP 大致是把陽性 findings 重抄一遍。
- **64% 是腫瘤病人，71% 有和前次比較**（stable、progression），74% 有測量值，32% 有標 se/im。
- 68% 掃到胸部，21% 掃到頸部，模型目前只看腹部。
- 約 42% 的 findings 句是陰性描述（No pleural effusion、Patency of portal vein……）。
- 格式依院區不同：LOC(8) 有 82% 用固定的「Findings:」樣板；LOC(2)、LOC(3) 格式比較自由（`<INDEX LESIONS>`、Major/Other findings、依 Neck/Chest/Abdomen/MSK 分段）。

### 1.3 結論

- 14 類分類器只能處理陰性描述和良性小發現，大約佔報告的四成。
- 醫師最花時間的是**找腫瘤病灶、測量、標 se/im、和前次比較**，目前沒有模型能處理。
- 如果直接拿這批報告訓練 LLM，會學到編造尺寸和「stable」，所以不在第一階段做。

## 2. 方案評估

| 方案 | 決定 | 理由 |
|---|---|---|
| 1. 分類結果 → 樣板 | **第一階段採用（加強版）** | 不會亂寫，錯誤可以追溯到分類器 |
| 2. 分類結果 → 訓練 LLM | 不做 | 輸入沒有新資訊，會學到編造位置和大小；要潤稿用 zero-shot Qwen 就好 |
| 3. embedding → LLM | 暫緩 | 很吃資料，幻覺多；報告內容大多依賴前次影像 |
| 4. 分類結果 + embedding → LLM | 第三階段候選 | 學習型方案裡最好的，但要先解決「比較前次」和病灶資訊 |
| 5. 原圖 → 報告 | 不做 | 運算量和資料量都不夠，也浪費 OWL encoder |
| A. 分割結果算定量數值 | **第一階段採用** | 確定性計算，不會有幻覺 |
| B. 檢索相似報告 + 改寫 | 第一階段 1b（潤稿用） | 輸出符合 CG 醫師的用語 |
| C. 按器官分段 | **第一階段採用** | 符合醫師的閱片和撰寫習慣 |
| D. 標示不確定性 | **第一階段採用** | 降低 automation bias |

## 3. 第一階段：結構化草稿（不訓練生成模型）

### 3.1 輸出長什麼樣

依院區格式輸出英文草稿，分成三種內容：

1. **模型判讀的器官**（14 類涵蓋的範圍）
   - 模型有把握是陰性：寫該院區最常用的陰性句（例如「No hydronephrosis.」）。
   - 模型有把握是陽性：寫該院區常用的陽性句，可以帶入定量數值。
   - 介於中間：寫陽性句並加上 `[please verify]`，不寫陰性句。
2. **模型沒判讀的器官**（胰臟、腎上腺、淋巴結、膀胱、肺底等）：放該院區的標準正常句，加上 `[NOT ASSESSED]` 標記，提醒醫師這幾句不是模型判斷的。
3. **留給醫師的段落**：Clinical information、Comparison、腫瘤病灶、IMP，只放空白標題。

### 3.2 步驟

| 步驟 | 內容 | 產出 |
|---|---|---|
| S1 句庫 | 把 10k 份報告切成句子，依院區（LOC）統計，再把句子對應到器官欄位（liver、GB/biliary、spleen、kidney、aorta、bowel、peritoneum、bone……）和陰性/陽性。用規則 + 關鍵字，難分的再用 Qwen 判斷 | `sentence_bank.csv`：LOC × 欄位 × 極性 → 最常見的寫法 |
| S2 切分資料 | 用 PID 把 6,970 例分成 dev（30%）和 test（70%），test 在定好 threshold 之前不看 | `split.csv` |
| S3 Threshold | 在 dev 上依定義 B 為每類選兩個 threshold：陰性門檻（敏感度 ≥ 0.95）和陽性門檻（特異度 ≥ 0.95），中間就是「請確認」 | `thresholds.csv` |
| S4 定量數值 | 先用已經有的 L1 HU；如果 CT-rate 上有 TotalSegmentator mask，再加脾臟體積和腹主動脈最大徑 | `measurements.csv` |
| S5 組裝 | 照院區格式把 S1、S3、S4 組成草稿 | `drafts/<EXAMID>.txt`、`drafts_test.jsonl` |
| S6 評估 | 見 3.3 | `eval_phase1.csv`、`eval_phase1.md` |
| S7（1b）潤稿 | 本地 Qwen 參考同院區的相似報告做潤稿，只改措辭不改發現；再用 S6 的方法確認潤稿沒有改到發現 | `drafts_polished/` |

### 3.3 評估方式

- **臨床正確性**：用產生 `disease14_qwen.csv` 的同一套 Qwen 抽取流程，從草稿反抽 14 類標籤，在 test 上和原報告標籤（定義 B）比較，算每類的敏感度、特異度、F1。
- **一致性檢查**：反抽出來的標籤要和組裝時的決策一致，用來確認句庫寫法能被正確理解。
- **涵蓋率**：原報告的陰性句有多少比例被草稿寫到、多少比例被草稿寫錯（原報告陽性但草稿寫陰性，**這是最需要壓低的錯誤**）。
- **人工抽查**：每個院區抽 10 份，原報告和草稿並排，給使用者或醫師看。
- BLEU、ROUGE 只當參考，不作為主要指標。

### 3.4 安全原則

- 原報告陽性、草稿卻寫陰性的錯誤，優先壓低；寧可多標「請確認」。
- 沒有被模型判讀的內容一律標 `[NOT ASSESSED]`。
- test 集在 threshold 鎖定之前不看。

### 3.5 檔案位置

- 程式：`VLM/code/CG/10000_data/report_gen/`
- 產出：`VLM/data/CT/CG/10000_data/report_gen/`（只放小檔；大檔放 CT-rate 的 Tony 資料夾）
- Qwen 抽取用 A6000 或 Spark 的 vLLM，檔案放在各台的 Tony 資料夾。

## 4. 第二階段：病灶偵測與測量（暫停）

範圍（2026-11-09 確認，之後暫停）：肝、腎、腹膜、淋巴結；胸部肺結節先不做。GPU：第二階段用 Spark，第一階段 S6 用 A6000。

先做的準備工作（和第一階段同時進行）：
- P2-1 病灶弱標籤：Qwen 從 10k 份報告抽出每個病灶的器官、位置、大小、se/im、性質、與前次比較 → `lesions_qwen.jsonl`
- P2-2 模型試跑：TotalSegmentator（liver tumor、腎囊腫）、SuPreM、DeepLesion 系列、ULS23，各跑 20–30 例並和 P2-1 比對

- 用病灶分割模型（通用病灶分割或肝臟病灶 nnU-Net）找出肝、腎、腹膜等處的病灶，自動測量長徑並標出 se/im。
- 用 Qwen 從報告抽出病灶敘述（器官、節段、大小、se/im）當作弱標籤，評估偵測和測量的準確度。
- 「和前次比較」需要前一次的影像；如果沒有，就只做單次偵測和測量，stable/progression 留給醫師判斷。

## 4.5 報告標準化（第三階段的前置作業，2026-11-09 新增）

CG 報告格式依院區差很多、同義寫法多、錯字多，還混著比較前次的內容和 disclaimer，直接拿來訓練會讓模型學到風格和編造。

**現行範圍（14 類）**：每份報告、每類疾病輸出 status（positive/negative/not_mentioned/uncertain）、原句、一句標準化句子（修錯字、mm、去掉時間比較用語）、屬性（嚴重度、側別、位置、尺寸）、和前次比較狀態。腫瘤病灶和其他器官內容不處理。下面是原本的全報告版做法，暫不執行：

1. Qwen 把 10k 份報告改寫成統一的按器官分段格式（Liver / Biliary-GB / Spleen / Pancreas / Adrenals / Kidneys-Ureters / Bladder-Pelvis / Bowel-Mesentery / Peritoneum / Vessels / Lymph nodes / Bones / Lung bases / Others），同時修錯字、統一單位為 mm、陽性和陰性分開。
2. 依賴前次影像的內容（stable、progression、和前次比較）、臨床資訊、掃描技術、disclaimer 各自拆到獨立欄位，不放進訓練目標。
3. 驗證：從標準化後的報告再抽 14 類標籤，和原報告標籤比對；不一致的抽查，確認改寫沒有漏掉或改到發現。
4. 輸出格式原則：內部一律用統一格式；交給醫師時再依院區風格輸出。

GPU：A6000 和 Spark 都可以用；A6000 上和第一階段 S6 共用同一個 vLLM server。

## 5. 第三階段：學習型生成（方案 4 + 檢索）

**2026-11-09 決定：**
- **主要目標：模仿 CG 醫師寫報告的風格。** 訓練目標用醫師的原句（標準化結果裡的 source_sentences，逐字、保留原本順序），依院區（LOC）條件化；標準化句子和屬性只拿來評估，不當訓練目標。依賴前次影像的用語（stable、progression、compared with）要拿掉；明顯錯字修正，其餘保留醫師原本寫法。
- 內容範圍：14 類疾病的句子，包含醫師寫的陰性句；屬性（側別、程度、椎體節段、AAA 直徑、脂肪肝分級等）要寫得準。
- 評估：疾病有無正確率（Qwen 反抽，不能比第一階段差）、屬性正確率、**風格相似度**（和同一檢查原報告的 BLEU/ROUGE/BERTScore、同院區 vs 其他院區的相似度、院區分類器能否分辨）；第一階段樣板草稿是 baseline。
- 資料切分：第三階段重新依 PID 切成 train 70% / val 10% / test 20%；和第一階段比較時，只用兩邊都屬於 test 的病人。
- 資料來源：先只用 CG；效果不夠再考慮加入 Merlin。
- 時程：準備資料 0.5–1 天 → 訓練（約 7B LLM + LoRA，A6000）→ 評估，第一版約 2–3 天。

原本的設計：

- 輸入：14 類結果 + 定量數值 + 病灶清單 + OWL token 特徵 + 檢索到的相似報告。
- 訓練資料：CG 10k（必要時加上 Merlin），先把依賴前次影像的句子和沒有輸入依據的尺寸遮掉。
- 和第一階段用同一套反抽評估比較，沒有勝過第一階段就不換。
