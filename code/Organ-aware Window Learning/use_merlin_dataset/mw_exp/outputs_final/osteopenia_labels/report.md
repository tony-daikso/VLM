# 骨質減少：標籤處理方式比較（LABEL_DECISIONS_PENDING #6）

日期：2026-11-06｜計算：Mac CPU（nice 10，每個流程 3 threads）；1.5 mm 切片在 A6000 以 nice 19 產生（只用 CPU，沒碰 GPU；沒用 Spark 或 CT-rate）｜**test 未讀取、未評分**｜A6000 `~/Desktop/Tony/VLM/OWL/mw_exp/outputs_final/osteopenia_labels/`

> **這是比較研究，不改正式標籤定義。** 正式標籤仍是「報告陽性（yes／probably_yes） vs 其他」。要不要改、怎麼改，由使用者決定。

## 結論
1. **B、C、D 這三種訓練端的標籤處理，在 val 上都沒有贏過 A。** 兩組 seed 結果一致：
   - B110（排除 HU<110 的報告陰性）：原始標籤 −.003／−.004，清理後標籤 +.001／−.001，都在雜訊內。
   - B130：原始標籤 −.007，CI 不跨 0，較差。
   - C（PU）：原始標籤 −.002／−.003，清理後標籤 ±.002。
   - D（soft label）：原始標籤 **−.018**，清理後 −.010，明顯較差。
   - D2（多任務堆疊，加 HU<110 head）：±.001，沒有差異。
2. **AUROC 的變動主要來自評估用哪一組標籤，而不是訓練方式。** 同一個 A 模型，原始 val .892，清理後 val **.909（+.017）**，符合錯誤分析估的 +.01～.025。但清理本身是用 HU 做的，所以這 +.017 有一部分是循環效應（見第 5 節）。
3. **模型的價值不只是 HU。**
   - 只用 −L1 HU（E）：原始 val .778，清理後 .807，都比 A 低約 .10。
   - 在同一 HU 區間內比較（HU 分層 AUROC），A 仍有 .84；E 依定義只有 .50。
   - 在 HU<110 規則的特異度（95.5%）下，A 的敏感度 45%，HU 規則只有 26%。
4. **C 的 train OOF 會誤導。** C 的 OOF 是 .917（A 是 .907～.908），只看 OOF 會選 C，但 C 的 val 只有 .889～.890。原因是 C 的 PU 權重來自 A 的 OOF 分數，這些分數由看過「當前 held-out fold 標籤」的模型產生，形成間接洩漏。要用 C，必須改成 nested PU，OOF 才能拿來選模。
5. **建議（決定權在使用者）**：訓練維持 A。若希望評估反映「影像上可見的骨質減少」，最誠實的做法是並列兩組指標：
   - 主要：原始 val。
   - 次要：清理後 val，並註明清理用到 HU，有循環性。
   - 另外加年齡配對 AUROC 與 HU 分層 AUROC。

   若真正想要的是「影像骨質疏鬆偵測」，應另立一個以 HU 定義的 finding，不要混進報告標籤。

## 1. 方法
- **模型**：和正式最佳（`osteopenia_v15` 的「5 個 window logit＋1.5 mm」）完全相同，只換標籤處理。
  - 3 mm lumbar_spine 的 6 個 window probe：E0、E3_late、E1×4。設定與 probe.py 相同：lr 1e-3、wd 1e-4、class-balanced BCE；early stopping 用 train 內 15% 的 holdout；E0 與 E3_late 各用 2 個 seed。
  - 1.5 mm L1–L4 逐節串接 LR：C=1e-4。
  - 堆疊：7 個分數輸入 LR，C=0.1。
  - **所有做法的超參數都固定為正式最佳選出的值**，所以差異只來自標籤處理。
  - fold 與 `analysis_osteopenia` 相同。年齡、性別從未作為模型輸入。
- **重現檢查**：A 重跑的 train OOF 為 .9075／.9068（兩組 seed），val .892；正式 v15 是 OOF .908、val .890。重跑之間的雜訊約 ±.002。
- **L1 骨小樑 HU**：`geom15_levels.csv` 中 L1 的 `hu_body`，也就是 v15 的 `hu15_L1`。計算方式是 1.5 mm seg15 椎體的正中矢狀面侵蝕 2 px 後取 HU 中位數。
  - 缺值：train 174 例、val 57 例，這些病例不重新標記。
  - 選這個值是因為覆蓋率 99%。錯誤分析用的 3 mm 核心 HU 只有 47% 的子集；在子集上兩者相關 .93，`hu15` 約低 10 HU。
- **各做法**（只改 train 的 target 或權重）
  - **A**：報告陽性=1，其他=0。
  - **B110／B130**：報告陰性且 L1 HU <110（或 <130）的病例權重設為 0，等同當作 unclear 排除。
  - **C（PU，Elkan-Noto）**：
    - 把 A 的 train OOF 堆疊分數做 Platt 校正，得到 g(x)=P(s=1|x)。
    - c = 已標記陽性的平均 g = **0.25**。
    - 未標記樣本的陽性機率 p = (1−c)/c · g/(1−g)，截在 [0,1]；每例拆成陽性權重 p 加陰性權重 1−p。
    - 估得盛行率 **15.3%**（報告盛行率是 4.7%）。
    - 沒有另外跑 nnPU。
  - **D（soft label）**：y_soft = max(報告, σ((110−HU)/10))；k=10 事先固定，沒有調整。
  - **D2（多任務堆疊）**：用 1.5 mm 逐節 LR 預測「L1 HU<110」（OOF AUROC .988），把它的 OOF 分數當第 8 個堆疊特徵；堆疊仍用報告標籤訓練。
  - **E**：分數 = −L1 HU，不訓練；另外計算 HU<110／<130／<160 二元規則。
- **評估**：都在 val 上進行，用兩組標籤。
  - 標籤組 (1) **原始**：報告標籤，5,034 例，陽性 235。
  - 標籤組 (2) **清理後**：去掉報告陰性且 HU<110 的 216 例，剩 4,818 例，陽性 235。
  - 指標：
    - AUROC：分層 bootstrap 95% CI（2,000 次）。
    - Δ：相對 A 的成對 bootstrap（2,000 次）。
    - 年齡配對 AUROC：10 歲一層；Δ 的 CI 用 500 次 bootstrap。
    - 年齡×性別層內 AUROC。
    - **HU 分層 AUROC**：在 <110／110–130／130–160／160–200／≥200 各層內計算，依配對數加權，用來衡量 HU 以外的鑑別力。
    - Spearman：分數 vs 年齡，只算陰性。
    - 90% 特異度下的敏感度。
  - 全部做法另以第 2 組 seed（seed1）重跑一次，檢查穩定性。

- 報告陽性中只有 26% 的 L1 HU<110。報告的「骨質減少」反映的是整體印象，包含 110–160 的灰色地帶、骨折、椎體成形術，而不是 HU 門檻。換句話說，「HU<110」和「報告陽性」是兩個不同的問題。

## 5. 循環性，以及模型是否只是在看 HU
- **清理後 val 的 AUROC 有一部分是循環的。** 被移除的 216 例，正好是「HU 低卻標為陰性」的病例。任何和 HU 有關的分數都會在這些病例上被扣分，所以把它們拿掉後，這類分數都會自動上升：A +.017，E +.029。因此清理後的 .909 不能直接當成「模型進步」。它代表的是：對照組限定為「報告陰性、且影像也不矛盾」時，模型的鑑別力。
- **E 遠遠追不上模型。**
  - 清理後 val：E .807，A .909。
  - 年齡配對：E .713，A .828。
  - 同一 HU 區間內，A 仍有 .84，E 是 .50。

  可見模型的鑑別力大多不是來自 L1 HU 本身，而是來自多節椎體、皮質、骨折與變形、整體骨質，以及與年齡相關的影像特徵。
- **年齡仍是主要混淆。** 各做法在陰性中的 Spearman（分數 vs 年齡）都在 .72–.76，年齡配對 AUROC 比原始 AUROC 低約 .09。D 把 target 往 HU 推，Spearman 反而升到 .757，年齡配對也掉最多（−.03），因為低 HU 本身就和高齡高度相關。

## 6. 各做法的臨床意義與優缺點
| 做法 | 回答的臨床問題 | 優點 | 缺點 |
|---|---|---|---|
| **A 原本** | 放射科醫師會不會在報告寫骨質減少／疏鬆？ | 標籤單純，與報告一致；val 和 OOF 最佳或並列最佳；不需要 HU | 約 690 例（數量約等於陽性）低 HU、報告「未提及」的病例被當陰性；學到的包括報告習慣與漏寫 |
| **B110 排除** | 同 A，但對「報告與影像矛盾」的病例不表態 | 直觀；訓練標籤較乾淨；對 val 無害（±.003） | 沒有增益；被排除的病例 64% ≥70 歲，等於挖掉最難也最重要的族群；部署時這些病人仍然會出現 |
| **B130 排除** | 同上，但排除範圍更寬（1,484 例，約陽性數的 2 倍） | — | 原始 val 顯著較差（−.007），年齡配對 −.012；排除太多高齡病例 |
| **C PU learning** | 不論報告寫不寫，這個人實際上有沒有骨質減少？（假設報告是隨機漏寫） | 理論上能處理「未提及≠陰性」；估得的盛行率 15% 較接近高齡族群的預期 | val 沒有增益；SCAR 假設（漏寫和影像無關）不成立，漏寫集中在灰色地帶；重新標記由模型決定，形成自我強化；**OOF 虛高**，要改成 nested 才能用 OOF 選模 |
| **D soft label** | 混合「報告」和「L1 HU<110」兩種定義 | 引入客觀的密度資訊 | 兩種定義衝突（報告陽性中只有 26% HU<110），模型被拉向 HU；val −.018；更依賴年齡 |
| **D2 多任務堆疊** | 仍是報告問題，多一個 HU head 當輔助特徵 | 無害；HU head 本身可當可解釋的副產品（預測 HU<110 的 AUROC .988） | 沒有增益；embedding 已含 HU 資訊，HU head 在堆疊中的係數為負（扮演抑制項） |
| **E 純 HU 門檻** | L1 骨小樑 HU 是否低於骨質疏鬆門檻？（機會性 CT 篩檢） | 不用訓練、可解釋、有文獻門檻，不依賴報告 | 以報告標籤評估只有 .78；敏感度低（26%）；只看一節，且受顯影相位與 ROI 影響 |

## 7. 建議（**最後由使用者決定**）
1. **訓練標籤維持 A。** B、C、D 在原始與清理後 val、兩組 seed 上都沒有可重現的增益，B130 與 D 明確較差。目前沒有理由為了訓練而改標籤。
2. **評估要用哪組標籤，屬於定義選擇，請使用者決定。** 可選：
   - (a) 只報原始 val（.892）。最保守，可直接和文獻、報告標籤比較。
   - (b) 並列清理後 val（.909）作為次要指標，並註明「排除報告陰性但 L1 HU<110 的病例；有用到 HU，屬部分循環」。val 與 test 都用同一規則，排除清單在看分數之前就用 HU 門檻定好。

   不論選哪個，都建議並列年齡配對 AUROC（目前約 .80／.83）。
3. 如果真正關心的是「影像上的骨質疏鬆」（機會性篩檢），比較乾淨的做法是**另立一個 finding**（例如 L1 HU<110，或 <100、<130），直接以 HU 為標籤和答案，和報告定義的「骨質減少」分開報告，做法類似脂肪肝、闌尾炎的拆分。D2 的 HU head（預測 HU<110 的 OOF AUROC .988）可以直接當作這個 finding 的模型。
4. 不建議 C，除非改成 nested PU；即使改了，SCAR 假設仍然不成立。

## 注意
- 各做法的超參數都固定為正式最佳的值，沒有個別重新選擇。B、C、D 理論上可能因此吃虧，但正式最佳的 C 網格在 OOF 上本來就很平，影響應小於 .002。
- D 的 k=10、B 的門檻 110／130 都是事先定好的，沒有用 val 調整。
- seed1 重跑全部做法，結論方向相同，Δ 的差異 ≤.002。
- 部署到 test 時，B 和清理後評估都需要 test 的 1.5 mm L1 HU（geom15 已經有）。要等使用者鎖定定義後才能讀取。
