# 脾腫大：錯誤分析（TotalSegmentator --fast 凍結 encoder，expB）

日期：2026-11-05。所有分析都在 **train 5-fold OOF** 上做（N = 15,202，陽性 971，盛行率 6.4%；unclear 107 例依 probe 規則設為 NaN）。val（N = 5,018，陽性 362）只列描述性數字，沒有用 val 調任何東西。**test 完全沒碰**：先依 split 過濾 id，才讀標籤與報告。

## 0. 重現性檢查

用 probe.py 的設定在 train 上重做 5-fold OOF：脾臟單元（finding_organ_map：`organs: [spleen]`）、12 個單元合併的 train 統計量做標準化、class-balanced BCE、Adam lr 1e-3 / wd 1e-4（expB 選定的 HP）。early stopping 用 train 內切出的 15%，不碰 val。跑 2 個 seed。與 probe.py 的差別：這裡只訓練脾腫大一個 finding，probe.py 是 14 個一起訓練。

| | train OOF | val（描述性） | expB 原始 val |
|---|---|---|---|
| E0 | 0.9645 | 0.9760 | 0.977 |
| E3_late | 0.9642 | 0.9796 | 0.980 |

結果可以重現。E3_late 的 gate 大致平均（0.18–0.22），多 window 對脾腫大幾乎沒有幫助。val 比 train 高約 0.01～0.015，原因是 **val 本身比較容易**：只用體積時，train 是 0.964、val 是 0.973。val 的陽性也比較大（體積中位數 637 vs 592 mL），mild 的比例比較低（27% vs 32%）。

### 假設 1：體積和頭尾長能不能解釋幾乎全部？**能。**

| 單一特徵 / 模型 | train OOF | val（描述性） |
|---|---|---|
| mask 體積（log mL） | **0.964** | 0.973 |
| 主軸長度（PCA 第一軸） | 0.956 | — |
| 3 軸乘積（spleen index） | 0.961 | — |
| 頭尾長度（z 範圍） | 0.936 | 0.947 |
| 體積 / L1 橫切面積（直接相除） | 0.951 | — |
| E3_late | 0.964 | 0.980 |

- embedding 可以用線性模型解出 log 體積，R² = **0.957**（5 個 window 都在 0.954–0.959）；頭尾長的 R² 是 0.88。也就是說，encoder 已經「知道」體積。
- 報告寫的長度和 mask 長度的相關：PCA 主軸 r = 0.87（mask 的中位數比報告長 1.3 cm）；z 範圍 r = 0.83（短 0.3 cm）。
- 臨床規則：主軸 > 13 cm 時，敏感度 0.97、特異度 0.78；z 範圍 > 13 cm 時，敏感度 0.66、特異度 0.96；體積 > 400 mL 時，敏感度 0.87、特異度 0.93。
- 醫師自己的判讀也不一致：報告有寫長度的 799 例中，**用報告長度本身預測標籤，AUROC 只有 0.926**。有 45 個陽性的長度 < 13 cm，也有 26 個陰性的長度 ≥ 13 cm。

### 假設 2：體型校正

直接相除反而變差（0.964 → 0.944–0.951），因為體型只解釋一小部分體積變異，相除會放大雜訊。改用 GBM 把體型當共變數：

| 特徵（GBM，同一組 fold） | train OOF | val（描述性） |
|---|---|---|
| 只用幾何 | 0.968 | 0.974 |
| 幾何 + 體型（L1 面積、前後徑、寬、椎體、FOV 長；不含年齡和性別） | 0.971 | 0.980 |
| 幾何 + 體型 + 肝、腎體積 | **0.973** | **0.981** |
| 幾何 + 年齡、性別 | 0.969 | 0.975 |

體型和器官大小有用；年齡和性別沒有額外幫助。肝體積可能部分反映「肝脾腫大」一起出現，在臨床上是合理的共變，但仍要留意。

## 3. 錯誤類別（train OOF，E3_late）

特異度 90% / 95% / 98% 時，敏感度分別是 **0.920 / 0.803 / 0.637**（E3_late + 幾何 GBM：0.922 / 0.843 / 0.636）。下面的類別可以重疊。

**FN（90% 特異度，78 例）**：mask 體積 < 陰性 p95（影像上不大）91%｜報告長度 < 13.5 cm 或 mild/borderline 68%｜mask 頭尾長 < 12 cm 64%｜肝硬化或門脈高壓 17%（陽性中佔 44%，所以 FN 中的比例偏低）｜不確定措辭 6%｜FOV 切到 1%｜脾臟缺如 1%

**FP（90% 特異度，1,423 例）**：mask 體積 ≥ 陽性 p10（影像上偏大）75%｜**明確寫 no 且大小正常 73%**｜男性 59%｜體型大 49%｜頭尾長 ≥ 13 cm 27%｜脾臟病灶 18%｜肝硬化或門脈高壓 12%（陰性中佔 4.8%）｜not_mentioned 10%｜報告有 mild/borderline 字眼 7%｜報告寫了 ≥ 13 cm 卻判陰性 1.5%

解讀：FN 幾乎都是「醫師判大、但體積不大」；FP 大多是「體積偏大、但醫師明確判正常」，常見於男性和體型大的人。這是醫師判讀門檻的差異，加上醫師沒有做體型校正，不是 embedding 看不到。

## 4. 天花板估計

- 灰色地帶（約 1,000 例）內，連體積的 AUROC 都只有 0.65。在有寫長度的子集，醫師用報告長度本身預測自己的標籤也只有 0.926。
- 最好的純影像模型（幾何 + 體型 + 器官大小，GBM）：train OOF **0.973**，val 0.981。
- 乾淨子集（明確的 yes，扣掉 borderline 與不確定措辭，vs 明確的 no）：E3_late 0.968、stack 0.973。只比全部高 0.004，因為主要問題在明確寫 no 的那些判讀，不在不確定措辭。
- **估計現行標籤下的天花板：train OOF 約 0.975–0.98，val 約 0.985**。E3_late 目前是 0.964（train）/ 0.980（val），**只剩約 +0.01（train）、+0.005（val）**。

## 5. 前三名修正（預期收益與成本）

1. **堆疊脾臟幾何與體型特徵**：log 體積、PCA 三軸長、頭尾長、最大橫切面積、FOV 切到旗標，加上 L1 橫切面積、前後徑、寬度、椎體面積、FOV 長度、肝與腎體積。用 GBM 和 E3_late logit 做 late stacking，不含年齡和性別。
   - 收益：train OOF **0.964 → 0.973（+0.009）**；val 描述性 0.980 → 0.982（**+0.002，95% CI −0.0003～+0.0056**，CI 跨 0）。不含肝腎體積的版本是 +0.0015。
   - 成本：低。特徵每例約 0.5 秒 CPU（`sp_geom.py`），train 和 val 都已算好；test 要等解鎖後用同一支程式產生。
   - val 增益很小，因為 val 本來就接近天花板。
2. **跑 test 前鎖定標籤邊界的定義**：probably_no（86 例，94% 是 borderline 或 upper limits of normal）和 borderline 措辭的陽性，另外歸成「邊界」，評估時設為 NaN 或另外報告。
   - 收益：評估 AUROC 拿掉 probably_no +0.001；如果連 mild/borderline 陽性都排除是 +0.013，但這是**評估定義改變**，不是模型變好。
   - 訓練時排除這些病例的實測：排除 not_mentioned 和 probably_no 後，E3_late OOF 0.964 → 0.965、val 0.980 → 0.980；排除 probably_yes/no 後，OOF 0.965、val 0.980。**訓練面幾乎沒有增益**。
   - 成本：低（規則半天）。要由使用者決定，並且在看 test 之前鎖定。
3. **加報告「體積參照」副指標，把資源轉去其他疾病**：以 mask 體積 > 400 mL（或依性別的門檻）當參考，報告模型和體積的一致性。這樣可以把「醫師門檻差異」和「模型錯誤」分開。
   - 收益：主 AUROC 不變，但能證明剩下的錯誤來自標籤門檻。
   - 成本：極低，特徵已經算好。
   - 理由：模型改良最多只能再多約 +0.005（val）。脾腫大是 14 個疾病中最接近天花板的，**不建議再投入 finetune 或新增 window**。
